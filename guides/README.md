# Guides

This directory holds reader-facing explanations of delivered behavior.

Name each file `<slug>.md`, using a unique kebab-case slug. Required frontmatter is `id: guide.<slug>` and `title`. Guides have no `status` lifecycle; revise them when the behavior they explain changes. Link the current sources a guide explains, such as public API declarations, type declarations, or the code that defines a behavior, with ordinary Markdown links. Historical context, when useful, is a sentence of prose. Workbench's [Keeping Current Specifications](https://markmals.github.io/workbench/guides/current-specifications/) describes where those sources live.
